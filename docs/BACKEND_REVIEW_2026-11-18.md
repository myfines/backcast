# 后端审查与改动记录（2026-11-18）

背景：后端负责人当时不在，用户让前端这边代为审查并补做讨论室所需的后端。改动都在分支 `feat/frontend-research` 上，没有动 `feat/zhihu-research`。请后端负责人回来后看一遍；不同意的地方可以直接回退对应提交。

## 审查发现的问题

| 严重度 | 问题 | 处理 |
|---|---|---|
| 高 | 公网会被刷光额度：创建讨论室、发消息、建画像、官方搜索、调查任务都没有鉴权和限流，共用同一份知乎凭证。25 秒调用间隔只存在于每个 `DebateModel` 实例里，多个请求同时进来就绕过了。 | 新增 `services/api/guard.py`：每个客户端的小时限流、全进程共享的调用间隔、每日总额度、繁忙时返回“服务繁忙”而不是无限排队。 |
| 高 | 讨论室会永久停在 `generating`：服务重启、连接断开或请求被取消后没有恢复（调查任务有，讨论室没有），前端会一直转圈且无法再发送。 | 启动时把遗留的 `generating` 标为失败；读取和发送时超过 10 分钟的视为中断；请求被取消时先保存再抛出。 |
| 中 | 分身回应常因“引用必须逐字存在”被拒，只试一次就把 502 抛给用户，演示成功率低。 | 校验类失败带着原因重试一次；模型或网络错误不重试（不重复花额度）。 |
| 中 | 失败的轮次也占用 12 次发言额度。 | 额度改按“已得到回应的轮数”计算。 |
| 中 | `POST /personas` 接受任意文字并挂上知乎链接作为“作者材料”，未核对文字确实来自该链接，公网上可被用来伪造某位作者说过的话。 | 设置 `PERSONA_ADMIN_TOKEN` 后，需要请求头 `X-Admin-Token`。本地默认不启用，公网部署务必设置。 |
| 低 | `/api/health` 不反映知乎官方凭证，前端无法提前提示。 | 增加 `official` 字段。 |
| 低 | 证据下载的内网地址检查是“先解析、后连接”，理论上有 DNS 重绑定窗口（本地单用户场景影响很小）。 | **未处理**，上公网前建议改为固定解析结果连接。 |
| — | 讨论记录页 HTML 已逐项转义，没有发现 XSS。 | 无需处理。 |

## 新增

`POST /api/v1/rooms/{id}/summary`：生成讨论总结（共识点、事实分歧、价值分歧、双方让步、仍待查证）。

- 每一条都带 `quotes: [{turn, quote}]`，后端校验该句逐字存在于对应发言中，否则重试一次，仍不通过返回 502，不保存编造的总结。
- 不判输赢；响应附带固定的 `note`。
- 至少有一轮分身回应才能生成；房间正在生成时返回 409。
- 总结保存在房间的 `summary` 字段，`GET /rooms/{id}` 会带出来。

## 新环境变量（均可选）

```dotenv
RATE_LIMIT_MODEL_PER_HOUR=40     # 每个客户端每小时调用模型的请求数
RATE_LIMIT_CREATE_PER_HOUR=20    # 每个客户端每小时创建的讨论室数
MODEL_DAILY_BUDGET=1500          # 全部客户端每天的模型调用总数
MODEL_MIN_GAP_SECONDS=25         # 全进程模型调用的最小间隔
MODEL_MAX_QUEUE_SECONDS=90       # 超过则返回“服务繁忙”
TRUST_PROXY=1                    # 在反向代理后面时，按 X-Forwarded-For 识别客户端
PERSONA_ADMIN_TOKEN=             # 设置后，创建作者分身需要 X-Admin-Token
```

这些限制都在进程内，只适用于单个 worker；多进程部署需要换成共享存储（如 Redis）。它们防的是额度被用光，不是身份认证。
